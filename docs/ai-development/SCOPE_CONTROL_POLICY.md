# Scope Control Policy

1. Existing approved TSR goals control the roadmap.
2. No new feature enters implementation without owner approval.
3. No new intelligence domain enters Milestone 1 without owner approval.
4. No new framework is created solely because it may be useful.
5. Infrastructure must serve TSR business-capability delivery.
6. Optional ideas remain separate proposals.
7. Codex may identify an idea but must not implement it.
8. ChatGPT must explain proposed ideas before requesting approval.
9. Every package defines approved and prohibited scope.
10. Every completion report discloses scope deviations.
11. Adjacent code convenience does not authorize package expansion.
12. Model selection waits for the approved benchmark gate.
13. Production orchestration waits for the approved production gate.
14. Deterministic legal and physical truck-safety controls remain authoritative.
15. AI, cost, scoring, prediction, explanation, or optimization cannot override those controls.
16. Supervisor Intelligence implementation requires an owner-approved work package.
17. Roadmap status changes require evidence.
18. A package cannot be marked complete solely from documentation claims.
